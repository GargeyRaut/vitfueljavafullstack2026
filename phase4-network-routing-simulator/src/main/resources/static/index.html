📘 Glossary

Router
A node in the network. In real life: a device that forwards packets. Here: just an id + label + up/down status.
Link
A connection between two routers, with bandwidth, latency, and reliability. Routing algorithms use latency as the "cost" of crossing it.
Latency
Fixed propagation delay (ms) for one hop across a link — think of it as physical distance/wire delay.
Bandwidth
How much data per second a link can carry (Mbps). Larger packets on lower-bandwidth links add extra queuing delay.
Reliability %
The chance a packet survives crossing a link. 95% reliability means roughly 1 in 20 packets gets dropped there.
Jitter
Random variation in latency between packets on the same route — shows up clearly when you batch-simulate many packets.
Hop count
How many links a packet crossed to get from source to destination.
TTL (Time To Live)
A safety limit on hops — if a packet bounces around longer than its TTL, it's dropped to prevent infinite loops.
Routing table
Each router's map of "to reach destination X, send the packet to neighbor Y next" — computed fresh before every simulation by the chosen algorithm.
Next hop
The very next router a packet is forwarded to — a router doesn't need to know the *whole* path, just the next step.
Fault injection
Manually setting a router or link to DOWN, to see how routing reacts to failures — click any status pill to toggle it.
Dijkstra
Always expands the closest not-yet-visited router next. Fast, and the basis for real protocols like OSPF.
Bellman-Ford
Repeatedly relaxes every link until distances stop improving. Slower than Dijkstra, but simple and robust.
Distance Vector
Each router only knows what its direct neighbors report ("I can reach X for cost Y") and gradually converges — this is how RIP and similar protocols actually work, without any router seeing the whole map.
Batch simulation
Fires many packets on the same route at once, to reveal the real loss % and latency spread instead of one random outcome.
Snapshot
A saved reading of the topology's size and average link latency at a point in time, stored in its own SQL table.

👋 New here?

This tool teaches network routing by letting you build a small network and watch packets actually move through it.

1. Create a topology (left panel) — or use the demo one that's already there.
2. Add a few routers and connect them with links (center panel) — hover the labels for hints.
3. On the graph: drag a router to reposition it, drag empty space to pan, scroll to zoom, right-click for quick actions. Click two routers to set source/destination.
4. Pick an algorithm and hit Run — watch the path light up and the event log fill in on the right.
5. Try toggling a link DOWN mid-way and re-running — see the route change.
6. Click the ? button any time for definitions, or open the 📘 Learn link up top for a full walkthrough of a routing concept.
