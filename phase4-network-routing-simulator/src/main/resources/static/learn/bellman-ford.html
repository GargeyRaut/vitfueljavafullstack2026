Level 4 — Routing

Bellman-Ford Algorithm

The routing algorithm that trades some of Dijkstra's speed for the ability to handle negative-weight edges.

1 · Overview

Bellman-Ford also finds shortest paths from a start node to every other node, but instead of greedily visiting nodes in distance order, it takes a blunter approach: relax every edge in the graph, repeat that up to (number of nodes − 1) times, and stop early if a full pass makes no improvements. It's slower than Dijkstra, but it doesn't rely on always picking the "closest" node next — which is exactly what makes it work with negative weights.

2 · Why it exists

Dijkstra's greedy strategy silently breaks if any edge weight can be negative — a "closest" node might not actually be closest once a later, cheaper (negative) edge is discovered. Bellman-Ford makes no such assumption: by blindly relaxing every edge over and over, it eventually finds the true shortest distances regardless of weight sign (as long as there's no negative cycle, which would make "shortest path" undefined in the first place).

3 · Real-world analogy

Imagine a rumor about the fastest fare between two cities. Instead of trusting the map's most "obviously cheap" route first (Dijkstra's approach), Bellman-Ford asks every travel agent in the whole network, one round at a time: "given what you knew before, has anyone found you a better deal?" After enough rounds of everyone comparing notes, the rumor settles on the true cheapest fare everywhere — even if some agent only became useful because of a surprising, deeply-discounted (negative-cost) leg.

4 · Technical explanation

1
Set distance to the start node = 0, every other node = infinity.
2
Repeat up to |V| − 1 times: go through every edge in the graph, and relax it (if going through the edge's source gives a shorter path to its target, update).
3
If an entire pass makes no changes, distances have already converged — stop early.
4
(A further optional pass can detect negative-weight cycles: if anything can still improve after |V| − 1 rounds, no shortest path is well-defined.)

6 · Step-by-step worked example (narrated)

Unlike Dijkstra, the order edges are relaxed doesn't change the final answer — only how many rounds it takes to fully settle. Running the demo above to completion always converges to the same result: A=0, B=2, C=4, D=7, E=-2. Notice E's distance is negative — something Dijkstra's algorithm can never produce, and would in fact handle incorrectly if you tried.

1
Round 1 relaxes the direct edges out of A, and whatever those unlock — several distances drop from infinity to a first estimate.
2
Round 2 catches improvements that depend on round 1's new estimates — notably, the negative edge B→E (-4) makes E cheaper than its first estimate.
3
Further rounds keep propagating any remaining improvements until a full round changes nothing.

7 · Common mistakes

Using Dijkstra instead, "because it's faster". Dijkstra is faster, but silently gives wrong answers the moment any edge is negative — there's no warning, it just computes the wrong shortest paths.
Forgetting the negative-cycle case. If a cycle's total weight is negative, "shortest path" has no lower bound (you could loop forever getting cheaper) — Bellman-Ford is also the standard way to detect that this has happened.
Assuming more rounds always find more improvements. Once a full round changes nothing, the algorithm has converged — running more rounds afterward can never improve anything further (in a graph with no negative cycle).

8 · Practical scenario

This simulator's own bellman-ford option uses non-negative link latencies (like Dijkstra) — real network hardware doesn't have "negative time" links — so on any topology you build here, both algorithms will always agree on the shortest path. Bellman-Ford's real practical niche is elsewhere: distributed distance-vector protocols like RIP are built on essentially the same "relax repeatedly" idea, just spread across many routers each relaxing their own local edges — which is exactly what the next lesson covers.

10 · Related concepts

Dijkstra's algorithm — faster, but breaks with negative weights.
Negative cycle — a loop with total negative weight, which breaks the very idea of "shortest path".
Distance vector routing — a distributed version of the same relax-repeatedly idea.
