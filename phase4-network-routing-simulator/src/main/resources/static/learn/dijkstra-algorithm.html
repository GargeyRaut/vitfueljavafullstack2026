Level 4 — Routing

Dijkstra's Algorithm

The exact shortest-path algorithm this simulator uses when you pick "dijkstra" — walked through one step at a time.

1 · Overview

Dijkstra's algorithm finds the cheapest path from one starting node to every other node in a weighted graph, by always exploring the closest unvisited node next. It never has to "backtrack" — once a node is visited, its shortest distance is final.

2 · Why it exists

Trying every possible path between two points gets astronomically expensive as a network grows. Dijkstra's insight — greedily expand the cheapest frontier node first — finds the guaranteed-optimal answer while only ever looking at each edge a handful of times. It's the basis for real link-state routing protocols like OSPF.

3 · Real-world analogy

Picture filling a room with water from a source point. The water reaches the closest walls first, then gradually spreads outward — by the time it reaches any given point, it has necessarily arrived via the shortest possible path from the source. Dijkstra's algorithm "floods" outward from the start node in exactly this order: always advancing to whichever unvisited point is currently closest.

4 · Technical explanation

1
Set distance to the start node = 0, and every other node = infinity.
2
Repeat: among all unvisited nodes, pick the one with the smallest known distance.
3
Mark it visited — its distance is now final and will never change again.
4
Relax each of its neighbors: if going through this node gives a shorter path than what's currently recorded, update the neighbor's distance and remember this node as its predecessor.
5
Repeat until every reachable node has been visited.

6 · Step-by-step worked example (narrated)

Running the demo above from start to finish on this graph produces exactly this sequence:

1
Visit A (distance 0). Relax B (→4) and C (→1).
2
Visit C (distance 1, the smallest so far). Relax B (1+2=3, better than 4 → update), D (1+8=9), E (1+10=11).
3
Visit B (distance 3). Relax D (3+5=8, better than 9 → update).
4
Visit D (distance 8). Relax E (8+2=10, better than 11 → update), F (8+6=14).
5
Visit E (distance 10). Relax F (10+3=13, better than 14 → update).
6
Visit F (distance 13). No unvisited neighbors left — done.

7 · Common mistakes

Assuming a shorter path can still appear after a node is visited. Once a node is visited in Dijkstra, its distance is mathematically final — this only holds because all edge weights are non-negative.
Using Dijkstra with negative edge weights. A negative edge could make a "later" path cheaper than an already-finalized one, breaking the algorithm's core guarantee. Bellman-Ford handles that case instead — see the simulator's other routing algorithms.
Confusing "visited" with "discovered". A node can have a known (even final) tentative distance from relaxation without being visited yet — visiting is a separate, deliberate step of picking the current minimum.

8 · Practical scenario

This is exactly what happens when you click Run simulation with the dijkstra algorithm selected back in the simulator: every router's latency to every neighbor becomes an edge weight, and the engine runs precisely this algorithm to compute the cheapest-latency path before sending the simulated packet along it.

10 · Related concepts

Bellman-Ford — a slower but more general alternative that tolerates negative weights.
Distance vector routing — achieves a similar result without any single node seeing the whole graph.
Priority queues — the data structure real implementations use to efficiently find the next closest node.
Longest Prefix Match — a different routing decision made after a path is already known.
