Longest Prefix Match

How a router picks the single best route when several routes could technically apply.

1 · Overview

A router's routing table often contains several entries that all technically match a given destination address — a broad one covering a whole provider network, and narrower ones covering specific subnets inside it. Longest Prefix Match (LPM) is the rule every IP router uses to pick exactly one of them: among all matching routes, use the one with the most specific (longest) prefix.

2 · Why it exists

Without a tie-breaking rule, a router with both 10.0.0.0/8 and 10.1.2.0/24 in its table would have no defined way to choose between them for a packet addressed to 10.1.2.5 — and different routers guessing differently would make the network unpredictable. LPM gives every router the same, deterministic answer: prefer specificity.

3 · Real-world analogy

It's like mail addressed with both a country and a street. If one rule says "anything for Japan goes to the Tokyo sorting office" and a more specific rule says "anything for this exact street goes directly to this local post office", the local post office — the more specific rule — wins, even though the country-wide rule also technically applies.

4 · Technical explanation

Every route in a routing table is a network/prefix-length pair, e.g. 192.168.1.0/24. To test whether a destination IP matches a route, the router:

1
Converts the destination IP and the route's network address into 32-bit binary.
2
Builds a mask from the prefix length — a run of that many 1-bits followed by 0-bits.
3
Applies the mask to both the destination IP and the route's network address (bitwise AND).
4
If the results are equal, the route matches. Among all matching routes, the one with the largest prefix length (the longest run of 1-bits — the most specific) is selected.

7 · Step-by-step worked example

Using the default table above and destination 192.168.1.130:

1
0.0.0.0/0 — matches everything (0 bits required). ✅ Match, prefix length 0.
2
192.168.0.0/16 — first 16 bits of 192.168.1.130 are 192.168. ✅ Match, prefix length 16.
3
192.168.1.0/24 — first 24 bits are 192.168.1. ✅ Match, prefix length 24.
4
192.168.1.128/25 — first 25 bits cover 192.168.1.128–255, and 130 falls in that range. ✅ Match, prefix length 25 — the winner, since 25 is the longest of all matching prefixes.

8 · Common mistakes

Assuming the first matching route wins. Real routers don't stop at the first match in table order — they evaluate all entries and pick the longest prefix, regardless of where it sits in the table.
Confusing prefix length with "how big the network is". A longer prefix (like /28) covers fewer addresses than a shorter one (like /16) — "longer" refers to more matching bits required, i.e. more specific, not "bigger".
Forgetting the default route always matches. 0.0.0.0/0 matches every address with zero bits of comparison — it's a safety net, and it always loses to any more specific route that also matches.

9 · Practical scenario

A company's router has a route to its whole ISP-assigned block (203.0.113.0/24) pointing out to the internet, and a second, more specific route to its own internal server subnet (203.0.113.128/28) pointing to an internal switch. Any packet addressed inside .128–.143 matches both routes — LPM ensures it's correctly sent to the internal switch instead of uselessly being routed out to the internet and back.

11 · Related concepts

Static routing — manually configured routes, of which LPM decides which one applies.
Default route — the /0 catch-all that always loses to a more specific match.
CIDR / subnetting — the addressing scheme that makes variable-length prefixes possible.
